# その日だけの送迎不要連絡

2026-10-02、ユーザーの追加依頼に基づく実装。対象は `/Users/brest/Documents/ChatGPT/欠席・振替` の `a466cc412ae38448d2f199db32c3ff9719f8ab32` を元にした独立コピー。直前の取消ロック修正と回帰テストを `fc5d3d2` で保存してから追加した。送迎機能は本番未反映。公開作業の状況は [RELEASE.md](./RELEASE.md) を参照。

## 保護者とスタッフの操作

1. 管理画面の「送迎連絡」→「送迎対象の登録・連絡コード」で、管理者が送迎名簿を確認した児童の名前、級、通常コース、普段利用する行き/帰りを登録する。コードはその場で一度だけ表示される。再発行すると古いコードと既存の保護者表示権限が無効になる。
2. 保護者はトップ画面の「出席するけれど、送迎を利用しない方へ」から `/transport` を開き、該当児童の送迎連絡コードを入力する。兄弟はそれぞれのコードを追加して選択する。欠席連絡の確認コードとは別。
3. 日付（日本時間）、行き不要/帰り不要/往復不要、任意の補足（300文字以内）を入力する。確認画面に児童、日付、「その日だけ」、便、出席予定を表示してから送信する。
4. 送信後と再読込後に保存した連絡を確認できる。管理者と既存のコーチ権限のスタッフが、各画面の「送迎連絡」で日付別の便・児童・補足を閲覧できる。「この内容を確認済みにする」は管理者のみ操作でき、保護者にも確認状況を表示する。スタッフの新規アカウントや恒久的な権限付与は行っていない。
5. 保護者は日本時間のレッスン開始直前まで、同じ日付で便・補足を訂正、または連絡を取り消せる。開始時刻と同時に新規・訂正・取消を締め切る。訂正・取消はスタッフ未確認へ戻り、取消も一覧に残る。日付の訂正は、元の日付を取り消して正しい日付に送信する2操作。
6. 退会・利用停止時は管理者が児童のコードを停止する。コードと保護者の表示・入力権限を無効化し、既存連絡を削除せず未確認へ戻す。再開は新しいコードの発行で行い、以前のコードは復活しない。実会員への発行・配布は実施していない。

出席・欠席・振替・定員は一切書き換えない。連絡は児童×日付で1件のみ。翌週や翌日へ自動継続しない。

## 現行アプリとの接続と制限

- 現行routerには保護者ログイン・児童アカウント画面が接続されておらず、認証APIも存在しない。稼働している確認コード方式を踏襲し、送迎専用コードでサーバーのセッションに児童ごとの権限を持たせた。未接続のログイン画面を有効化したわけではない。
- `transport_profiles` はスタッフが確認して登録する専用の送迎名簿。既存 `users` / `children` や外部会員名簿とのID連携・実データ取込は行っていない。既存の公開欠席APIが氏名入力方式のため、出席との照合も正規化氏名・級・通常コース/対象日を使う保守的な確認。名簿内の同名重複は受付を止めて確認を促す。会員IDによる厳密な照合は今後の連携判断が必要。
- 通常コースの曜日・時間・級に合うレッスン枠が登録され、休講でない日が対象。欠席連絡がある日は受付を止める。遅刻は欠席として扱わない。
- 確定した振替予約がある日は通常の送迎予定を引き継がず、スクールへの確認を表示する。振替日の配車が存在するかを判断できるデータがないため、振替日の送迎不要送信は未対応。通常日への誤った適用を防いでいる。
- 送信後に欠席・休講等へ変わる場合は、スタッフ一覧に出席予定の再確認を表示する。連絡取消は開始時刻前のみ可能。欠席等と送迎送信を一括トランザクションにしておらず、一覧を取得した時点の照合結果を表示する。
- メール機能は欠席/振替等の保護者向け文面で、今回のスタッフ送迎確認に使える既存の通知はなかった。誤った欠席メールは再利用せず、日付別一覧と本日未確認件数、30秒ごとの更新を追加した。送迎メール/プッシュ通知/配車システム連携は未実装。外部実送信は0件。

## 日付・更新・権限

- 日付はPostgreSQLの `date` と `YYYY-MM-DD` 文字列で保持し、今日の判定・表示は日本時間。端末のタイムゾーンに依存しない。存在しない日付や日時文字列は拒否する。
- ユーザーの指定により、入力・訂正・取消は当該レッスンの開始時刻まで。サーバーが既存の正規レッスン開始時刻を参照し、行ロックの待機後にも時刻を照合する。開始時刻を特定できなければ受付を止める。画面だけが古い状態でもAPIで拒否し、既存連絡は参照できる。
- コードは144bitの乱数で、DBにはSHA-256ハッシュだけを保存。氏名やIDのみでは連絡の取得・編集・取消を許可しない。コードによる児童の表示権限は12時間、コード停止・再発行で即時失効。コード自体は停止・再発行まで利用可能。失敗した入力はIPごとに15分間15回まで。コードや補足をAPIレスポンスログに書かない。
- 管理者は登録・停止・再発行・確認済み操作が可能。既存のコーチ権限は一覧閲覧のみ。保護者・匿名・コーチによる管理者専用APIの呼び出しを拒否する。
- 同時二重送信は児童行ロックと児童×日付のユニーク制約で1件にまとめる。同じ内容の再送はバージョンを増やさない。訂正・取消はバージョン照合し、古い画面からの上書きは409で拒否する。スタッフの確認済み操作も対象バージョンと一致する時だけ保存する。
- 保存対象は送迎専用2テーブルのみ。既存の取消修正は保持し、別児童の予約人数を守る回帰テストも再実行した。
